
# Network Traffic Analysis – Mini SOC Home Lab

## 1. Investigation Overview

**Investigation Type:** Network Traffic Analysis  
**Date:** October 30, 2026  
**Environment:** Windows 10  
**SIEM:** Splunk Enterprise  
**Log Source:** Sysmon  
**Event ID:** 3 – Network Connection  
**Analyst:** SOC Analyst Tier 1 Lab

## 2. Objective

Analyze network connections generated by applications and Windows processes using Sysmon and Splunk.

The objective was to identify communication patterns, destination IP addresses, network ports, and potentially suspicious connections.

## 3. Tools Used

- Splunk Enterprise
- Splunk Universal Forwarder
- Sysmon
- Windows 10
- Splunk Search Processing Language (SPL)

## 4. Investigation Process

Sysmon Event ID 3 was used to investigate network connections.

The initial investigation identified traffic from:

- Google Chrome
- Spotify
- Discord
- NVIDIA Overlay
- Windows svchost.exe
- Splunk services

Connections were analyzed by destination IP, destination port, protocol, and process name.

## 5. Key Findings

### Localhost Communication

Several connections were associated with Splunk components using 127.0.0.1.

Examples:

- Splunkd.exe – TCP 8089
- PostgreSQL – TCP 5432
- Splunk Universal Forwarder – TCP 9997
- KV Store – local TCP communication

These connections were consistent with internal Splunk services.

### DNS Traffic

Destination IP:

`24.138.252.19`

Observed applications:

- Google Chrome: 1,571 events
- Spotify: 818 events
- Windows svchost.exe: 316 events
- NVIDIA Overlay: 107 events
- Discord: 82 events
- Microsoft Edge WebView2: 52 events
- Microsoft Edge: 3 events

Destination port: 53/UDP

The shared destination and port are consistent with DNS resolution activity.



### HTTPS / QUIC Traffic

Several applications generated network traffic over destination port 443.

Examples included:

- Spotify
- Google Chrome

Depending on the transport protocol, port 443 traffic may represent HTTPS over TCP or QUIC over UDP.

The destination IP and port alone are insufficient to determine whether a connection is malicious.




```spl
index=main sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational"
| rex field=_raw "<EventID>(?<EventCode>\d+)</EventID>"
| search EventCode=3
| rex max_match=0 field=_raw "<Data Name='(?<fieldname>[^']+)'>(?<fieldvalue>[^<]*)</Data>"
| eval pairs=mvzip(fieldname,fieldvalue,"=")
| eval Image=replace(mvindex(mvfilter(match(pairs,"^Image=")),0),"^Image=","")
| eval DestinationIp=replace(mvindex(mvfilter(match(pairs,"^DestinationIp=")),0),"^DestinationIp=","")
| eval DestinationPort=replace(mvindex(mvfilter(match(pairs,"^DestinationPort=")),0),"^DestinationPort=","")
| eval Protocol=replace(mvindex(mvfilter(match(pairs,"^Protocol=")),0),"^Protocol=","")
| table _time Image DestinationIp DestinationPort Protocol
| sort -_time
```

### Connection Statistics

```spl
index=main sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational"
| rex field=_raw "<EventID>(?<EventCode>\d+)</EventID>"
| search EventCode=3
| rex max_match=0 field=_raw "<Data Name='(?<fieldname>[^']+)'>(?<fieldvalue>[^<]*)</Data>"
| eval pairs=mvzip(fieldname,fieldvalue,"=")
| eval Image=replace(mvindex(mvfilter(match(pairs,"^Image=")),0),"^Image=","")
| eval DestinationIp=replace(mvindex(mvfilter(match(pairs,"^DestinationIp=")),0),"^DestinationIp=","")
| eval DestinationPort=replace(mvindex(mvfilter(match(pairs,"^DestinationPort=")),0),"^DestinationPort=","")
| eval Protocol=replace(mvindex(mvfilter(match(pairs,"^Protocol=")),0),"^Protocol=","")
| stats count by Image DestinationIp DestinationPort Protocol
| sort -count
```

## 7. Analyst Assessment

The observed traffic was largely consistent with normal application activity, DNS resolution, local network discovery, and internal Splunk communications.

No confirmed malicious network connection was identified during this investigation.

This assessment is limited to the Sysmon events collected and analyzed. Further investigation would be required to establish the reputation and ownership of destination IP addresses or confirm the domains resolved through DNS.

## 8. Investigation Limitations

- Sysmon Event ID 3 provides connection metadata, not the full network payload.
- DNS domain names were not available because no corresponding Sysmon Event ID 22 events were found in the analyzed data.
- Destination IP ownership and reputation were not independently verified.
- The investigation reflects only the events collected during the selected time period.
